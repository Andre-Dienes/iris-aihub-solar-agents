# Presentation script (≈ 15 minutes)

Before starting: container up, page open at `http://localhost:52773/api/solar/ui`, Management Portal open in
another tab (*Interoperability → Production* of the SOLAR namespace). With an OpenAI key the badge shows
**LLM: OpenAI**; without one, **offline mode** (steps 1 to 5 work the same way).

## 1. The problem (1 min)

Four solar plants, three data sources (inverter telemetry, weather, maintenance). Everyday questions require
crossing sources, writing SQL and interpreting numbers. Goal: AI agents **inside IRIS**, next to the data, with
full traceability.

## 2. Simple question → text-to-SQL (2 min)

Chip: **"What was the energy and the PR of each plant in August 2026?"**

- **Graph** tab: path `triage → identify → plan → call_agents → synthesize → finalize`.
- The table comes from SQL generated by the Telemetry agent (the *Agent: Telemetry* mode shows the SQL).
- **Trace** tab: every node, every `%AI.Provider` call (model, tokens, ms) and every vector search.

Talking point: *"the graph is declared in XData; the agent is a `%AI.Agent`; the SQL goes through guardrails —
SELECT only, and only over the agent's tables."*

## 3. Multi-agent root cause (3 min)

Chip: **"Why did the PR of Blue Ridge drop in August 2026?"**

- The `plan` node calls **all three agents**: the daily series shows the drop from Aug 10 to Aug 18, weather
  rules out rain as the main cause, maintenance finds the critical failure of **INV-03** (64 h down).
- The **integrated analysis** cross-checks the evidence and recommends actions.
- In the portal, open the message **Visual Trace**: `Gateway → Agent.Router → Agent.Telemetry / Weather / Maintenance` —
  every agent is a Business Process.

## 4. RAG, language and self-correction (2 min)

- **"What is Performance Ratio?"** → CONCEPT branch, answer grounded on the glossary stored as native vectors.
- **"Which plant had the best performance ratio in July 2026?"** → when the LLM gets the SQL syntax wrong, the
  path shows `execute → fix_sql → execute` (the IRIS error goes back to the LLM).
- **"What was the energy?"** → vague question: the graph branches to `ambiguous` and asks for plant and period.
- Bonus: ask in Portuguese (*"Qual foi o PR da usina Aurora em agosto de 2026?"*) — the answer comes back in Portuguese.

## 5. Autonomous assistant + skill + action (4 min) — requires a key

Mode **Autonomous assistant**, chip **"Diagnose Blue Ridge in August 2026…"**

- The LLM activates the **performance-diagnosis** skill (`%AI.Agent.Skill`) and picks the tools on its own:
  `CalculatePR` (two periods), `QueryAgent` (telemetry, maintenance, weather).
- The IEC 61724 PR calculation is **Embedded Python**.
- It **offers** to open a maintenance work order. Answer: **"Yes, open the work order for INV-03 with High priority."**
- Same session (persisted `%AI.Agent.Session`) → work order **WO-xxxxx** shows up in the *Work orders* tab and in
  the Visual Trace (`Gateway → WorkOrders`, a Business Operation).

## 6. Opening up to the ecosystem (1 min)

- The same 8 tools are published at `/mcp/solar` (`%AI.MCP.Service`) for Claude Desktop, VS Code and other MCP clients.
- `curl -H "X-IRIS-MCP-Server: 1" http://localhost:52773/mcp/solar/v1/services` shows the catalog.

## 7. Wrap-up (2 min)

- No LangChain, no external vector database, no third-party Python packages: **one IRIS container**.
- Graph (predictable, auditable, runs offline) + assistant (flexible) in the same framework.
- Tests: `do ##class(SolarAgents.Tests.DemoTest).Run()` — 12 offline tests.

## Plan B

- No internet or no key: run steps 2 to 4 only (offline mode) and show the assistant through the README images.
- Slow LLM responses: offline mode answers in under 1 second.
